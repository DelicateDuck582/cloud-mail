## 1. 修复思路

审计发现的核心问题不是"线上不安全"，而是**仓库与线上不一致**：
- 线上 `cos.duckgame-play.top` 实际运行的 cos-exchange Worker 是**最新最安全**的版本；
- 但该源码**未纳入 git**（只在 `web开发\cos-proxy-worker.js`），仓库 `doc/cos-proxy-worker.js` 是滞后快照，仍残留 4 个生产版已修复的安全缺陷。

因此本轮核心动作：**把线上生产版回灌仓库 `doc/cos-proxy-worker.js`**，使仓库成为"单一事实源"；再对 mail-worker / mail-vue 做低危加固。

## 3. 修复清单

### 3.1 COS（核心）— `doc/cos-proxy-worker.js`

将线上生产版（`web开发\cos-proxy-worker.js`，2082 行）整体同步到仓库 `doc/cos-proxy-worker.js`（原 1152 行 → 2082 行）。
同步后 SHA256 与生产版一致：`655661B5862ADD5240C70B825EC9A4BA92223C42382119D641126035B8C5384F`。

由此消除仓库旧版残留的 4 个安全缺陷：

| # | 缺陷（仓库旧版） | 修复（生产版已有） |
|---|---|---|
| 1 | `ATT_SIGN_MAX_TTL` 非数字时 `Number()`→NaN，**TTL 上限整体失效**（超长签名被放行） | `Number.isFinite` 兜底回默认 3600（已实测：配 `'abc'` 时 2h 签名被拒） |
| 2 | browse cookie 用 **FNV-1a 32 位哈希** + `===` 比较（可碰撞、弱密码可字典反推） | **HMAC-SHA256 指纹** + 独立密钥 + `timingSafeEqual` |
| 3 | `/browse/api/list` 出错时把含 `ourSTS/cosSTS/sentUrl` 的整段 JSON **回给客户端**（泄露 COS 桶地址与签名中间值） | 仅回 `error` 字段，调试细节只留服务端日志 |
| 4 | `loginFailMap` 无容量上限（海量不同 IP 可撑爆内存） | 新增 `loginFailGC` 定期清理 + 上限兜底 |

同时附带同步了生产版的其它增强：COS 健康探测与宕机页、`/browse/logout`（HttpOnly cookie 服务端清除）、`per_page` 分页与 prefix/token 长度限制、下载路径反斜杠拦截、Range 透传、附件 `Cache-Control: private`、误部署到跳转目标的防自杀式重定向等。

### 3.2 mail-worker 低危加固

| 文件 | 改动 | 原因 |
|---|---|---|
| `src/utils/sign-utils.js` | 新增 `timingSafeEqual`（恒定时间比较，与 cos-exchange/oauth 一致） | 提供统一实现 |
| `src/index.js` | `/attachments/` KV 直读签名比较 `!==` → `signUtils.timingSafeEqual` | 防时序侧信道 |
| `src/api/r2-api.js` | `/oss` 直读签名比较 `!==` → `signUtils.timingSafeEqual` | 同上 |
| `src/service/oauth-service.js` | `bindUser` 的 `update(oauth)` 补 `await` | 正确性：绑定后立即查询可能读到旧 `userId` |
| `src/service/turnstile-service.js` | `remoteip` 增加合法 IP 正则校验，非法时**不传**该参数 | 对齐 cos-exchange，避免 siteverify 误拒 |

### 3.3 mail-vue 前端

| 文件 | 改动 | 原因 |
|---|---|---|
| `src/views/reg-key/index.vue` | 邀请码生成 `Math.random()` → `crypto.getRandomValues()` | `Math.random` 可预测，邀请码有被碰撞/猜测风险（后端 `genRandomPwd` 已用 CSPRNG，此前前端漏改） |

## 7. 遗留待办（未纳入本轮，建议后续处理）

1. **`vitest.config.js` 指向不存在的 `wrangler.jsonc`** → 跑单测需临时配置；且本机 `@cloudflare/vitest-pool-workers` 与运行时版本不匹配（`node:vm` 解析失败），建议升级工具链或改跑 Node 环境配置。
2. **`test/index.spec.js` 是陈旧的 "Hello World" 测试** → 与真实 worker 不符，跑全量必然失败，建议删除或重写。
3. **`x-forwarded-for` 作为 IP 回退**：非 CF 直达路径下 XFF 可伪造（绕过登录防爆破/限流）。生产全量走 CF 无影响，建议后续统一只信任 `CF-Connecting-IP`。
4. **`stalwart-sync/` 未跟踪目录含真实凭证**（Tunnel Token / admin 密码占位）：立即移出仓库 + 轮换曾填写的 token。
5. **OAuth `state` 固定值（CSRF）**：上游设计 `state=${provider}`，建议后续改为随机 state + sessionStorage 校验（非账号接管，中低危）。
6. **`wrangler-test.toml` 含真实测试 D1/KV ID**：建议占位符化。
