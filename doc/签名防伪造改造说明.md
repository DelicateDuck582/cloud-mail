# 签名防伪造改造说明（CloudMail + COS 前置 Worker）

## 一句话原理

伪造 Referer / Sec-Fetch 之所以能得手，是因为这两层只验证"头长什么样"。
这次加的是**只有后端能签发的东西**：

```
CloudMail 读邮件时给每个附件 URL 追加：
  https://cos.duckgame-play.top/attachments/<key>?expires=<unix>&sign=<HMAC>

代理 Worker 对 /attachments/ 路径强制验签：
  没有 sign / sign 不对 / 已过期  -> 403，连 COS 都不会碰
```

`sign` 是用 `ATT_SIGN_SECRET` 算的 HMAC-SHA256。攻击脚本伪造不了它，
因为密钥只存在你的 Cloudflare Worker 环境变量里（后端一份、代理一份），
**任何人伪造 Referer + Sec-Fetch 全套头都算不出合法签名** → 之前的理论缺口彻底堵死。

## 改动清单

### 后端 CloudMail（mail-worker）—— 共 4 个文件

| 文件 | 改动 |
|---|---|
| `src/utils/sign-utils.js` | **新增**。签名工具：`signKeys` / `signContent`（正文 `{{domain}}` 占位符加签名）/ `addAttUrl`（附件列表加 `url` 字段） |
| `src/service/email-service.js` | 新增 `signEmailList`；在 `list` / `latest` / `allEmailLatest` / `allList` / `send` 返回前统一加签名；`imgReplace` 剥离签名参数防写回库 |
| `src/service/att-service.js` | `list` 改为异步并给附件加 `url`；`toImageUrlHtml` 剥离签名参数防 key 污染 |
| `src/service/star-service.js` | 星标列表返回前调用 `emailService.signEmailList` |

### 前端 mail-vue —— 1 个文件

| 文件 | 改动 |
|---|---|
| `src/views/content/index.vue` | 附件下载/预览优先使用后端返回的签名 `url`（`att.url`），缺失时回退 `cvtR2Url(att.key)` |

### 代理 Worker —— 1 个文件（全量替换）

`cos-proxy-worker.js`（本目录）：在原有双层校验之上加了签名强制校验；
已升级为 **Workers Cache API 按文件缓存（按 path，TTL 7 天）**：附件 key 是内容哈希，
文件不变则哈希不变，同一文件只需回源一次；每个请求**都先验签**再查缓存，命中缓存不会绕过签名校验。
（另：只对 GET 写入缓存，避免 HEAD 请求污染同路径缓存；仅代理 `/attachments/` 与 `/static/` 两类路径。）

**签名相关修复记录**：
- 签名密钥链使用**二进制字节**推导（与 AWS SDK 一致）；若误用 hex 字符串当密钥会得到错误签名 → `SignatureDoesNotMatch`；
- 密钥/地域/endpoint 读取时 `trim()`（CF 环境变量粘贴常带尾随空白）；
- 回源失败（429/5xx）自动重试一次，并返回 `X-Upstream-Status` 头便于区分限流来源（CF 还是 COS）。

## 需要配置的环境变量

1. 生成一个随机密钥（任选其一）：
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   # 或 openssl rand -hex 32
   ```
2. **CloudMail Worker（mail-worker）** 新增：
   - `ATT_SIGN_SECRET` = 上面的密钥
   - `ATT_SIGN_TTL`（可选，默认 `900`，即 15 分钟；范围 60~86400）
3. **COS 代理 Worker** 新增：
   - `ATT_SIGN_SECRET` = 同一个密钥（必须完全一致）
   - `ATT_SIGN_MAX_TTL`（可选，默认 `3600`，校验时限制签名的最大有效时长）
4. 两个 Worker 都重新部署，前端重新构建发布。

> 注意：`ATT_SIGN_SECRET` 只在两个 Worker 的环境变量里，不会出现在任何
> URL 或浏览器代码中。

## 部署后的行为

| 请求 | 结果 |
|---|---|
| 邮件页正常看图/下载（后端签发的新签名 URL） | ✅ 200 |
| 地址栏直开 / 其他网站盗链（无签名） | ❌ 403 |
| curl 伪造 Referer + 全套 Sec-Fetch 头（无签名） | ❌ 403 |
| 拿着过期签名重放 | ❌ 403（签名过期 + 边缘缓存同步过期） |
| 登录页背景图 `static/background/...`（保持原 Referer/Sec-Fetch 校验） | ✅ 200 |

## 边界说明

- `attachments/` 下所有文件（内嵌图、附件）都必须签名；`static/background/`
  登录背景不要求签名（它本来就是公开展示的，维持原双层校验）。
- 邮件正文里 `{{domain}}` 占位符在后端读邮件时动态签名，**不落库**，
  所以已收的旧邮件无需迁移。
- 转发/回复时编辑器里的签名 URL 会在发送流程中被自动剥离签名参数再入库，
  不会把过期签名写回库内。
- `/public/emailList` 开放 API 返回的是原始 `{{domain}}` 占位符，不在本次
  签名范围内（如需开放 API 也出图，可在 `public-service.js` 里同样调用
  `signEmailList`）。

## 安全与费用的关系（为什么缓存 7 天也不怕）

签名有效期默认 15 分钟、缓存按内容哈希存 7 天：
- 验签**先于**缓存查找：无签名/伪造/过期签名 → 403，根本到不了缓存；
- 同一文件（内容哈希不变）在 7 天内只需回源一次，之后所有**合法签名**请求直接命中边缘缓存，COS 流量 0；
- 攻击者拿不到新签名，刷的永远是 403；即使拿到一条 15 分钟内的合法链接，也只能触发
  每个边缘节点最多一次回源，之后全部命中缓存，COS 流量上限极小；
- 注意：Workers Cache API 是「尽力而为」缓存，内存压力下可能提前淘汰（属正常现象，偶尔多回源一次）。

## 附：/browse 只读文件浏览器（可选功能）

同一个 cos-exchange Worker 内置了个人只读网盘 `/browse`（无服务器方案）：

- 手机/电脑访问 `https://cos.duckgame-play.top/browse` → 密码登录 → 像网盘一样浏览桶内文件夹、下载/预览；
- 界面：卡片/表格双视图、图片缩略图（IntersectionObserver 懒加载 + 并发限流）、图片灯箱、PDF/视频/音频/文本内嵌预览、搜索/类型筛选/排序、深色模式、Windows 式详情侧边栏；
- 所有请求都经本 Worker 回源 COS，不直连 COS 默认域名；文件按 key 缓存 7 天；
- 纯只读：只有 ListObjectsV2（列目录）+ GetObject（下载），没有任何上传/删除接口；
- 环境变量：
  - `BROWSE_PASS`（访问密码，**必设**，未配置时 `/browse` 拒绝服务）
  - `BROWSE_ALLOW_COUNTRY`（可选，如 `CN`，只允许指定地区的 IP 访问）
  - `TURNSTILE_SITEKEY` / `TURNSTILE_SECRET`（可选，登录页人机验证）
- 防刷流量：登录失败 5 次/10 分钟锁定 + 每次 1s 延迟；列表 40 次/分钟、文件 120 次/分钟 per-IP 限流；Cookie `HttpOnly + Secure`；
- 只读子账号策略需同时含 `GetObject` + `GetBucket`（列目录需要）；
- `/browse` 与附件签名体系相互独立：附件仍必须验签，浏览凭密码门控。
